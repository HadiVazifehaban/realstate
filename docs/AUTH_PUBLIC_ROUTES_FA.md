# سیاست مسیرهای عمومی و خصوصی شکارچی

این سند وضعیت پیاده‌سازی مسیرهای Next.js و API را ثبت می‌کند. نام یا پیشوند مسیر به‌تنهایی سطح دسترسی را تعیین نمی‌کند.

| مسیر | دسترسی | کنترل |
|---|---|---|
| `/` | عمومی | صفحه موجود، تغییر مسیر داخلی به `/dashboard/properties` |
| `/dashboard/properties` | عمومی | استثنای صریح در Proxy و Layout؛ API فهرست فقط املاک فعال را می‌دهد و مختصات را مبهم می‌کند |
| سایر مسیرهای `/dashboard/*` | احراز هویت‌شده | نیازمند Session Auth.js؛ مقصد اولیه در `callbackUrl` نگه داشته می‌شود |
| `/api/v1/properties` و `/api/v1/properties/cities` با GET | عمومی | فقط فهرست فعال/شهرهای دارای ملک فعال؛ DTO عمومی؛ پارامتر وضعیت نمی‌تواند شرط ACTIVE را خنثی کند |
| سایر عملیات `/api/v1/properties/*` | احراز هویت‌شده | اعتبارسنجی Principal در FastAPI |
| `/api/v1/admin/*` | فقط مدیر | توکن معتبر و نقش `ROLE_ADMIN` |
| سایر APIهای داده‌دار | احراز هویت‌شده | گارد Router و بررسی JWT سمت FastAPI |

## ورود و نشست

دکمه ورود از Header به Auth.js و Provider مربوط به Keycloak می‌رود. مقصد بازگشت فقط وقتی پذیرفته می‌شود که مبدأ آن با مبدأ برنامه یکی باشد. Auth.js از OIDC/PKCE و refresh token استفاده می‌کند. برای APIهای فعلی که مستقیم از مرورگر به FastAPI می‌روند، Access Token در Session سمت کلاینت قابل دسترسی است؛ تغییر این معماری به BFF نیازمند انتقال فراخوانی‌های API است.

OTP عمومی FastAPI برای اثبات شماره و ثبت‌نام باقی مانده است؛ در `AUTH_MODE=KEYCLOAK` مسیر قدیمی صدور نشست با password grant پاسخ `409 oidc_required` می‌دهد. پس از ثبت‌نام، ورود از Auth.js و SMS Authenticator خود Keycloak انجام می‌شود. حالت آفلاین `LICENSE` برای سازگاری قدیمی نگه داشته شده است.

در توسعه LAN، آدرس فعلی HTTP است؛ Keycloak هشدار می‌دهد که Cookieهای Secure در این context فعال نیستند. این هشدار با خطای بارگذاری Factory ارتباطی ندارد. محیط عملیاتی باید HTTPS و Proxy Headerهای معتبر داشته باشد. این تغییرات عملیاتی در این کار انجام نشده‌اند.

- تست واحد سیاست دسترسی API و گارد ادمین اجرا شده است.
